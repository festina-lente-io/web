# Data Model: Project Showcase Website

**Feature**: Project Showcase Website
**Created**: 2025-12-25
**Technology**: Hugo with Hextra theme

## Entity Definitions

### 1. Project Content

Represents a project showcase page with quickstart documentation.

**Attributes**:
- `title` (string, required): Display name of the project
- `description` (string, required): Brief description (50-150 words)
- `repo_url` (string, required): GitHub repository URL
- `weight` (integer, optional): Display order (lower = higher priority, default: 10)
- `draft` (boolean, optional): Draft status (default: false)
- `date` (datetime, optional): Creation date
- `lastmod` (datetime, optional): Last modification date
- `type` (string): Content type, typically "projects"

**Content Sections** (in markdown body):
1. Prerequisites
2. Installation
3. Quick Start
4. Next Steps
5. Troubleshooting
6. FAQ
7. Advanced Usage

**File Location**: `/content/projects/{project-slug}.md`

**Example**:
```markdown
---
title: "DevToys MCP"
description: "A Model Context Protocol (MCP) server that provides developer tools and utilities directly in Claude Desktop. Simplifies common development tasks like JSON formatting, base64 encoding, and more."
repo_url: "https://github.com/festina-lente-io/devtoys-mcp"
weight: 10
draft: false
date: 2025-12-25
type: "projects"
---
```

### 2. Homepage Content

Represents the main landing page showcasing all projects.

**Attributes**:
- `title` (string, required): Page title
- `description` (string, optional): Meta description for SEO
- `layout` (string, optional): Hugo layout template (default: "home" or theme default)
- `type` (string): Content type, typically "home" or left empty

**Content Structure**:
- Hero section with site introduction
- Project portfolio (auto-generated list or manual curation)
- Optional: About section, mission statement

**File Location**: `/content/_index.md`

**Example**:
```markdown
---
title: "Festina Lente - Open Source Projects"
description: "Discover open source projects maintained by Festina Lente, including developer tools, standards, and utilities."
type: "home"
---

# Welcome to Festina Lente

Explore our collection of open source projects designed to improve developer productivity and code quality.

## Featured Projects

Browse our projects below to find quickstart guides, documentation, and GitHub repositories.
```

**Validation Rules**:
- `title`: 1-100 characters
- `description`: 50-160 characters (SEO optimal)

**Relationships**:
- Parent to all project pages
- Referenced in site navigation

### 3. Site Configuration

Represents Hugo site-wide configuration and Hextra theme settings.

**Attributes** (in `hugo.toml`):
- `baseURL` (string, required): Full site URL with protocol
- `title` (string, required): Site title
- `theme` (string, required): Theme name ("hextra")
- `languageCode` (string): Language code (default: "en-us")
- `enableRobotsTXT` (boolean): Generate robots.txt (default: true)
- `enableGitInfo` (boolean): Use git info for lastmod (default: true)

**Hextra Theme Parameters**:
- `params.description` (string): Site description
- `params.author` (string): Site author/organization
- `params.navbar.menu` (array): Navigation menu items
- `params.footer.copyright` (string): Footer copyright text

**File Location**: `/hugo.toml` (or `config.toml`)

**Example**:
```toml
baseURL = "https://www.festina-lente.io/"
title = "Festina Lente"
theme = "hextra"
languageCode = "en-us"
enableRobotsTXT = true
enableGitInfo = true

[params]
  description = "Open source projects for developers"
  author = "Festina Lente"

[params.navbar]
  [[params.navbar.menu]]
    name = "Home"
    url = "/"
    weight = 1
    
  [[params.navbar.menu]]
    name = "Projects"
    url = "/projects/"
    weight = 2

[params.footer]
  copyright = "© 2025 Festina Lente. Open source projects."

[markup]
  [markup.goldmark]
    [markup.goldmark.renderer]
      unsafe = true  # Allow raw HTML in markdown

[module]
  [[module.imports]]
    path = "github.com/imfing/hextra"
```

**Validation Rules**:
- `baseURL`: Must be valid HTTPS URL ending with `/`
- `theme`: Must be "hextra" or valid Hugo theme
- Navigation menu items must have valid URLs

### 4. Navigation Item

Represents a menu item in site navigation (auto-generated or configured).

**Attributes**:
- `name` (string, required): Display text
- `url` (string, required): Target URL (relative or absolute)
- `weight` (integer, optional): Sort order (lower = first)
- `external` (boolean, optional): Opens in new tab (default: false)

**Sources**:
- Manual: Defined in `hugo.toml` under `params.navbar.menu`
- Automatic: Generated from content sections by Hextra

**Example** (manual in `hugo.toml`):
```toml
[[params.navbar.menu]]
  name = "GitHub"
  url = "https://github.com/festina-lente-io"
  weight = 100
  external = true
```

**Example** (automatic from content):
- Hugo generates navigation from content structure
- Project pages appear under "Projects" section
- Hextra theme handles rendering

**Validation Rules**:
- `name`: 1-50 characters
- `url`: Valid URL or path starting with `/` or `http`
- `weight`: Positive integer

### 5. GitHub Actions Workflow Configuration

Represents CI/CD pipeline configuration for build and deployment.

**Attributes**:
- `name` (string): Workflow name
- `on` (object): Trigger conditions (push, pull_request, etc.)
- `jobs` (object): Build, test, deploy jobs
- `env` (object): Environment variables (Hugo version, etc.)

**File Location**: `.github/workflows/deploy.yml`

**Example Structure**:
```yaml
name: Deploy Hugo Site

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

env:
  HUGO_VERSION: "0.120.0"

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          submodules: true  # Fetch Hugo themes
          
      - name: Setup Hugo
        uses: peaceiris/actions-hugo@v2
        with:
          hugo-version: ${{ env.HUGO_VERSION }}
          extended: true
          
      - name: Install GitVersion
        uses: gittools/actions/gitversion/setup@v0.10.2
        
      - name: Determine Version
        id: gitversion
        uses: gittools/actions/gitversion/execute@v0.10.2
        
      - name: Build
        env:
          HUGO_VERSION_TAG: ${{ steps.gitversion.outputs.semVer }}
        run: hugo --minify
        
      - name: Test with htmltest
        run: |
          curl -s https://htmltest.wjdp.uk | bash
          ./bin/htmltest
          
      - name: Deploy
        if: github.ref == 'refs/heads/main'
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./public
          cname: www.festina-lente.io
```

**Validation Rules**:
- Must trigger on `push` to `main` branch
- Must include build, test, and deploy steps
- Must use Hugo Extended version

### 6. GitVersion Configuration

Represents semantic versioning configuration.

**Attributes**:
- `mode` (string): Versioning mode ("Mainline", "ContinuousDelivery", etc.)
- `branches` (object): Branch-specific version rules
- `increment` (string): Default version increment ("Patch", "Minor", "Major")

**File Location**: `GitVersion.yml`

**Example**:
```yaml
mode: Mainline
branches:
  main:
    tag: ''
    increment: Patch
  feature:
    tag: 'feature'
    increment: Minor
    is-mainline: false
```

**Validation Rules**:
- Mode must be valid GitVersion mode
- Branch names must match git branch patterns

## Data Flow

```
Content Authors
    ↓
Project Markdown Files (/content/projects/*.md)
    ↓
Hugo Build Process
    ├→ Hextra Theme (rendering)
    ├→ GitVersion (version injection)
    └→ Minification/Optimization
    ↓
Static HTML/CSS/JS (/public/)
    ↓
GitHub Actions (testing)
    ├→ htmltest (link validation)
    ├→ Lighthouse CI (performance)
    └→ pa11y (accessibility)
    ↓
GitHub Pages (deployment)
    ↓
CDN (www.festina-lente.io)
    ↓
End Users
```

## Content Lifecycle

1. **Creation**: Author creates markdown file in `/content/projects/`
2. **Draft**: Set `draft: true` for unpublished content
3. **Review**: Git commit, pull request, peer review
4. **Build**: Hugo generates static HTML
5. **Test**: Automated tests validate quality
6. **Deploy**: GitHub Actions pushes to `gh-pages` branch
7. **Publish**: GitHub Pages serves content at custom domain
8. **Update**: Edit markdown, repeat cycle

## Schema Evolution

**Adding New Projects**:
1. Create new markdown file: `/content/projects/new-project.md`
2. Follow front matter schema
3. Include all 7 required sections
4. Commit and push (auto-deploys)

**Modifying Project Schema**:
1. Update all existing project files
2. Document schema change in migration notes
3. Update data-model.md (this file)
4. Commit as single atomic change

**Breaking Changes**:
- Require migration script for bulk updates
- Document in constitution compliance notes
- Version bump (major version)

## Validation

**Build-Time Validation**:
- Hugo validates front matter YAML syntax
- Required fields checked by theme templates
- Broken internal links fail htmltest
- Missing images detected by htmltest

**CI/CD Validation**:
- Front matter schema validated by tests
- Content structure validated (7 sections present)
- External links checked (with timeout tolerance)
- Accessibility standards enforced (pa11y)
- Performance thresholds enforced (Lighthouse CI)

**Manual Validation**:
- Peer review in pull requests
- Local preview before commit (`hugo server`)
- Staging environment testing (feature branches)
